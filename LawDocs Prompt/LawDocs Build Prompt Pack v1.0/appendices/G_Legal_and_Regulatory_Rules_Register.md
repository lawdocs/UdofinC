## G.0 How to use this register

**Purpose.** This register lists the legal rules that **drive LawDocs behaviour** — hard blocks, gates, clocks, thresholds, disclosures, routing choices and conduct limits — so that engineers encode them as data in `rul` (P03 FR-P03-54) with a citation, a reviewer of record and a golden test, and so that authors cite a row instead of re-stating law. It is not a legal treatise: content explaining the law to users lives in templates, help keys (`hlp.*`) and tutorials, each citing an `LG-*` row.

**Identifier policy.** `LG-001`…`LG-172` are R3's IDs, unchanged (R3 left gaps; gap numbers are **reserved and never assigned**). Rows added by this appendix start at **`LG-173`** and are allocated in blocks by domain (table in G.0.3). IDs are never reused; a superseded row keeps its ID with status `SUPERSEDED` and a pointer.

### G.0.4 Next-review rule (FR-P03-60)

`VERIFIED` rows: 180 days → **2027-04-23**. `SECONDARY`/`CARRIED`: 90 days → **2027-01-23**. `[VERIFY]` rows: **2026-11-24** or earlier if the dependent flag is requested ON. **Volatile** rows (marked `vol`) are reviewed every 30 days regardless of status → **2026-11-24**: DPDP commencement, IT Rules 2026 timelines, CCA ESP licence list, TCCCPR 2026, RB-IOS 2026 clauses, RBI recovery-conduct amendments, State stamp-duty tables in a budget month, Income-tax Act 2025 section mapping, app-store payment rules. An overdue row raises an owner item (`wf.items`), a console banner, and its declared fallback applies to new decisions.

### G.0.5 Rules for engineers

1. Code never hard-codes a legal number. It reads a `rul` parameter that cites an `LG-*` row (`NN-30`); `help-key-lint` and `rule-cite-lint` fail the build on an uncited legal constant.
2. Every row used in code has at least one positive and one negative golden case named `LG-NNN_*` (`packages/rules/fixtures/legal_register/`), plus the NN test where an NN applies.
3. An amendment creates a new row **version** (`LG-096 v2`) with `effective_from`; old versions stay for replay of past decisions (instances pin the version that decided them, FR-P03-59).
4. A `[VERIFY]` row cannot be the sole basis of a feature that is ON in production; the feature's flag carries `requires_verification_id` = the `V-*` item in Appendix W (FR-P00-50; NN-38).
5. Tenants may tighten, never loosen, a protective row (FR-P03-61). Rule challenges by tenants are answered within 10 working days.

## G.1 Rule-row schema used by the `rul` engine

The register runs as platform rule set **`IN.rul.legal_register`** (domain `legal_register`, effect class per row) stored in `rul.rule_sets` / `rul.rule_set_versions` (P03 §7.2); each version's `content` is an array of rows conforming to JSON Schema **`ld.legal_rule.v1`** (in `packages/rules/schemas/`). Rows are also registered as content kind `legal_rule` in `rul.content_kinds` so that templates, clauses and help articles can cite them. No new table is introduced.

| Field | Type | Required | Notes |
|---|---|---|---|
| `rule_id` | string `^LG-\d{3}[A-Z]?$` | Y | Stable; e.g., `LG-096A` exists in R3 |
| `version` | int | Y | Starts at 1; increments on amendment |
| `title` | string ≤ 120 | Y | Plain English |
| `domain` | enum | Y | `ESIGN`, `IDENTITY`, `DIGILOCKER`, `PRIVACY`, `EVIDENCE_COURTS`, `STAMP_REGISTRATION`, `CONTRACT_PROPERTY`, `CORPORATE`, `RBI`, `INSURANCE`, `CONSUMER`, `PROFESSIONAL`, `TAX`, `LABOUR`, `IP`, `MOTOR`, `TELECOM`, `ACCESSIBILITY`, `FOREIGN_PRIVACY`, `CONTRACTUAL` |
| `jurisdiction` | string | Y | `IN`, `IN-<ST>` (State), `EU`, `UK`, `US-CA` |
| `instrument` | object | Y | `name`, `number` (e.g., `S.O. 4720(E)`), `issuer`, `date`, `gazette_ref` |
| `provision` | string | Y | Exact section/rule/para/clause |
| `effective_from` / `effective_to` | date / date null | Y / N | Transition notes in `commencement_note` |
| `requirement` | text | Y | ≤ 80 words |
| `parameters[]` | array | N | `{key, value, unit, setting_key}` — e.g., `{key: "filing_window_days", value: 90, setting_key: "chp.rbios.filing_window_days"}`; values only here, never in code |
| `effect_class` | enum | Y | `protective`, `computational`, `permissive`, `emergency_block` (FR-P03-56) |
| `tier` | enum | Y | `L` Locked (no tenant may loosen), `G` Governed (content team changes by versioned release with maker-checker), `T` tenant may tighten |
| `implications[]` | array | Y | `{phase, fr_ids[], nn_ids[], ch_ids[], setting_keys[], error_codes[], flags[]}` |
| `verification` | object | Y | `status` (`VERIFIED`/`SECONDARY_ONLY`/`NOT_CONFIRMED`), `research_confidence` (`V-WEB`/`V-SEC`/`V-REG`/`VERIFY`), `sources[]` `{key, url, retrieved_on, sha256}`, `open_points[]`, `verification_ids[]` (Appendix W `V-*`) |
| `reviewer_of_record` | object | Y at activation | `{name, role_code, qualification, registration_no, reviewed_on}`; must differ from `maker` (`LD-RUL-011`) |
| `maker` | user ref | Y | `PLT_CONTENT_EDITOR` or `PLT_LEGAL_REVIEWER` |
| `next_review_due` | date | Y | Per G.0.4 |
| `volatile` | bool | Y | 30-day review when true |
| `fallback` | enum | Y | `advisory_only`, `block`, `manual_route`, `hide_feature` |
| `tags[]` | enum | Y | `[LAW]`, `[INTERP]`, `[REC]`, `[CONTRACT]`; plus `[COUNSEL]`, `[TAX MEMO]`, `[OWNER]` with the open-item ID |
| `supersedes` / `superseded_by` | rule ref | N | Version chain |
| `golden_cases[]` | refs | Y at activation | ≥ 1 positive, ≥ 1 negative |

## G.23 Update procedure

**Triggers.** (a) A monitored source changes (e-Gazette, regulator circular page, CCA ESP list, UIDAI, NeGD, TRAI, IP India, State stamp notifications, MCA, CBIC, Income-tax portal); (b) a row reaches `next_review_due`; (c) a `V-*` item in Appendix W is closed; (d) a tenant rule challenge (FR-P03-61); (e) counsel or tax-memo output; (f) an incident or regulator query; (g) a vendor contract changes terms (ESP, eStamp, KYB, court data).

**Procedure (maker-checker, NN-18, NN-30).**

| Step | Actor | Action | Output |
|---|---|---|---|
| 1 | `PLT_CONTENT_EDITOR` (maker) or monitoring agent (`AGT_` regulatory watcher, maker only — NN-43) | Open a change request on `IN.rul.legal_register` citing the source (URL, retrieval date, SHA-256 of the PDF) and the affected `LG-*` rows; draft the new row version and plain-language summary | `cfg.change_requests` record; `RuleSetVersionSubmitted` |
| 2 | Maker | Update golden cases (≥ 1 positive, ≥ 1 negative per changed row); run preview diff on in-flight objects (counts only across tenants) | Green golden suite or accepted mismatches with reasons |
| 3 | Reviewer of record (`PLT_LEGAL_REVIEWER` with the RoR role in the row; `PLT_DPO` for privacy; tax adviser for tax) — must differ from maker (`LD-RUL-011`) | Read the primary text; set `verification.status`; record name, qualification, registration number, date | Row `APPROVED`; verification-log entry (`V-*` closed or opened) |
| 4 | Owning function (P08 stamp duty; P15 consumer clocks; P14 tax) for computational rows; `PLT_SUPER_ADMIN` publisher for permissive rows | Approve values and scheduling | `SCHEDULED` with `effective_from` and propagation mode (`prospective` default; `open_items_with_notice`; `emergency_block`) |
| 5 | System | Activate at `effective_from`; pin decided objects; send "What changed" notice to affected tenant admins (≤ 120-word summary, citation, action) | `RuleSetVersionActivated`; notices |
| 6 | Maker | Update dependent phase text, templates, help keys and website copy in the next content release (never a code release); update Appendix W and this appendix's change log | Content versions referencing the new row version |

**Emergency path.** An ESP licence lapse, a takedown-timeline change in force immediately, or a court order affecting a feature uses `emergency_block` signed by `PLT_LEGAL_REVIEWER` + `PLT_SECURITY_OFFICER`; post-incident review within 5 working days (FR-P03-56).

**Volatile watch-list (30-day cadence).** LG-005, LG-038, LG-061, LG-062, LG-070, LG-077, LG-097, LG-123, LG-171–LG-181, LG-354, LG-417–LG-422, LG-450–LG-452.

**Annual full review.** Every October the content team re-reads every `VERIFIED` row against its primary source and re-signs; the review report is filed in `docs/compliance/rules-register-annual-review-<YYYY>.md` and linked from P23's evidence pack.

**Never.** Never edit a row in place after activation; never let a code release change a published row; never activate a permissive row on `SECONDARY` evidence; never cite a withdrawn or superseded instrument as current.
