# PART A — Template contract v2.0 *(v1.2)*

Part A is binding for every template, import and export from pack v1.2. Where Part A and Part B differ, **Part A prevails**. Part B (§E.0–§E.18) remains in force for the rules Part A reuses (normalisation §E.4.1, multi-value parsing §E.4.2, due-rule grammar §E.4.4, citation parsing §E.4.5, weblink tokens and the official-domain allowlist §E.4.6, markers §E.4.7, the registry §E.6, error codes LDC-TPL-001–048 §E.7.2, change sets §E.9, tenant import §E.10, AI authoring §E.11, security §E.14, and the family C/D vocabularies §E.15), and for the legacy v1.0 importer path (§A.9).

The tables in Part A marked "generated" are produced by `templates/_build/v12_appendix_tables.py` from `templates/_build/v12_contract.py`, the same module the template builder and validator use. Change the contract module first, then regenerate; never edit a generated table by hand.

## A.0 Decision and reasons *(v1.2)*

Management instructed on 25 October 2026 that the owner's 30-column sheet was a reference only. It cannot be read on one screen, exported or printed properly. Decision D-49 replaces the v1.0 contract (D-08) with **contract v2.0**. NN-35 is amended to read: "The template contract (group order, machine keys, header text and base vocabularies) is immutable within a major template version; families add extension columns and values but never rename or remove base ones; v1.0 sheets are accepted through the legacy map."

The design follows the pattern used by mature GRC and work-management tools, which pair a short list with a record panel that opens beside it (P04 §4R). In Excel the same pattern is built from native features only: outline column groups, freeze panes, AutoFilter, data validation, print titles and a print area. No macros are used, so the file stays macro-free and safe to import (§E.14).

| Problem with the v1.0 sheet | v2.0 answer |
|---|---|
| 30 columns, no single-screen view | Nine yellow **LIST VIEW** columns are always visible. The other seven groups are Excel outline groups, collapsed by default and opened with the "+" buttons or the outline-level buttons 1 / 2 / 3 |
| Cannot be printed or exported cleanly | Print area = list view (A:I), A4 landscape, one page wide, rows 1–2 repeated. Exports carry the list columns plus Next Due, Days to Due, RAG and Maker (D-50) |
| No instrument identity or version per row | **SOURCE & VERSION** group: instrument name, reference, issue date, last amended date, **Actionable Last Updated On** (per row), Change Status and Change Note |
| Same columns and lists for every entity | 62 base columns plus **0–4 family extension columns** inside APPLICABILITY. Each family has its own dropdowns |
| Department was the only grouping | **Department → Function → Sub-function** dependent dropdowns, so filters, exports and heat maps can group three levels deep |
| CompID typed by authors | CompID is left blank and **generated on import** (D-52). It is unique, immutable and never reused (NN-56) |
| No risk or governance register | `LDC-TPL-RISK-v2.0` (RiskID) and `LDC-TPL-GOV-v2.0` (GovID) in the same design (D-57) |

## A.1 Design principles *(v1.2)*

| # | Principle | Enforcement |
|---|---|---|
| A-P1 | Read by machine key, not column letter | Each row-2 header resolves to a key through the contract of the template version. Extension columns move later letters, so letters are never used (P03 FR-P03-100; LDC-TPL-051, 072) |
| A-P2 | List view first | Nine LIST VIEW columns at A:I, frozen at D3; every other group collapsed (validator T12) |

| A-P6 | Soft lists for open sets, closed lists elsewhere | Authority, Event Trigger and the GOV Governing Body and Timing columns use warning alerts, so values outside the list are allowed but flagged. Multi-value columns never block in Excel. All other list columns use stop alerts |

| A-P8 | Deterministic build | All 29 workbooks are generated by `v12_build_templates.py` and checked by `_validate_templates_v2.py` (15 tests). The report must read 29/29 PASS before release |

## A.6 Department → Function → Sub-function (generated) *(v1.2)*

**Mechanism.** The `Lists` sheet carries two matrices after the flat lists: **FUNCTIONS by Department**, with one column per department (header row 1, functions below), and **SUB-FUNCTIONS by Function**, with one column per function. The Function dropdown in each row uses a formula (shown for RBI-NBFC, where Department is column E and Function is column AC):

```
OFFSET(RBI_NBFC_FuncTop,0,MATCH($E3,RBI_NBFC_FuncHdr,0)-1,
       COUNTA(OFFSET(RBI_NBFC_FuncTop,0,MATCH($E3,RBI_NBFC_FuncHdr,0)-1,60,1)),1)
```

The Sub-function dropdown uses the same formula with `SubTop`, `SubHdr` and the Function column. The formulas stay under Excel's 255-character limit and work in Excel and LibreOffice; the builder test evaluated them in LibreOffice ([Create a drop-down list](https://support.microsoft.com/en-us/excel/get-started/create-a-drop-down-list); [Apply data validation to cells](https://support.microsoft.com/en-us/excel/get-started/apply-data-validation-to-cells)). **Values.** For the nine base departments, the functions and sub-functions are the Part-2 master §10A orientation map plus platform additions. Family departments carry their own functions. A function with no specific sub-functions uses the generic list. Function names are unique within a family, and the builder asserts this. Tenants may add functions and sub-functions to their overlay vocabulary (`cfg.tenant_vocab_values`, §E.6) and rename them for display; canonical codes are kept.

## A.8 CompID assignment and business IDs (D-51, D-52, NN-56) *(v1.2)*

**Authors leave `comp_id` blank.** LawDocsComply generates the CompID when the sheet (or an AI Studio draft) is imported. A number is **reserved** at preview and **assigned** at publication (P03 FR-P03-103–104). Exported sheets carry CompIDs, and a re-import updates the same items: blank → new; a known CompID → update, no change or retire (FR-P03-105). An unknown, foreign, retired or duplicate CompID raises LDC-TPL-076–080 (P03). The sequence engine (one database row per scope, block reservation, `UNIQUE` constraints) makes collisions impossible even under concurrent imports.

**Grammar** (P03 FR-P03-101). Platform: `<AUTH>-<FAM>-<INST>-<NNNN>`, regex `^[A-Z]{2,6}-[A-Z0-9]{2,8}-[A-Z0-9]{2,8}-[0-9]{4,6}$`. Tenant: `T<TENANT4>-<INST>-<NNNN>`. A compliance instance is `<CompID>/<PERIOD>[/<ENTITY>]`.

- AUTH is the authority code.
- FAM is the hyphen-free `fam_short`. Appendix B holds the master.
- INST is the instrument short code, of the form `<SUBJECT><YY>`. It is at most 8 characters, immutable once the first CompID is reserved (LDC-TPL-087), and records the instrument of first publication.
- NNNN is never reused. The sequence widens to five digits only after 9,999 in one scope.

For cross-authority families, AUTH is the issuing authority of the instrument.

## A.9 Legacy v1.0 → v2.0 map (generated) *(v1.2)*

v1.0 workbooks are recognised by sheet `Sheet1` with `Rough`, or by a `_Template_Info` code ending `-v1.0`. They are kept in `templates/_legacy_v1.0/`, still validated by `_validate_templates.py` (27/27 PASS), and imported through this map, which is held in `tpl.legacy_maps` (P03 FR-P03-112).

- Instrument name, reference and dates are taken from the file name, or from the catalogue row chosen in the upload dialog, with a confirmation step.
- `question_updated_date` defaults to the instrument issue date.
- `change_status` defaults to `New`. If the row starts `[RETIRED] `, it is set to `Retired` (LDC-TPL-056).
- `dept_function` is left blank, and the content maker completes it before publication.
- `risk_type` is proposed from the compliance type and department and needs confirmation.

The owner's existing NBFC and IFSCA sheets therefore import without rework.

### A.11.2 Grouping and order

- **Group keys** (up to three levels): Department → Department Function → Department Sub-function; Compliance Type; Risk Type; Risk Category; Regulator; Instrument; Legal entity; Due month (`next_due`, `YYYY-MM`); Due week; RAG; Status; Owner.
- **Multi-value Risk Type.** By default an item is grouped under its primary (first) Risk Type. With the "list under every type" option it appears under each, and the totals note the duplication.
- **Order within a group:** RAG severity (Red, Amber, Blue, Green, Grey), then Days to Due ascending, then Risk Category High → Low.
- **Summary sheet:** export metadata, then three matrices — group × RAG, primary Risk Type × RAG and Due month × RAG — with SUM formulas for row and column totals.

### A.11.3 Identity, ledger and re-import

- **Identity.** Every export carries `export_id` and the export identity block (§A.2.1), and has a protected `_Export_Info` sheet. P04 writes events `cmp.ListExportRequested`, `cmp.ListExportGenerated` and `cmp.ListExportDelivered`, with a ledger entry per included CompID (NN-57).
- **Re-import.** A Working Register uploaded to the content importer is recognised by `export_kind`. Its User and System groups are ignored (LDC-TPL-065), and Author-column changes by a tenant become overlay proposals (§E.10). Bulk status updates use the P04 bulk-update tool, never the content importer.
- **Limits.** Rows above `cmp.export.max_rows` (default 100,000) are refused (LDC-CMP-202, P04). The PDF format is limited to `tpl.export.pdf_max_rows` (default 5,000); above that the user is offered Excel.

## A.12 RAG as written to exports (summary of P04 FR-P04-230) *(v1.2)*

P04 owns the rules (`cmp.rag.rules`, `cmp.rag.high_risk_widen_pct`). Exports write the RAG and Days to Due computed at the export timestamp, and the PDF cover states the rule set in force (NN-58).

The rules apply in order, and the first match wins:

1. Not applicable, exempted or withdrawn → **Grey**.
2. Event based with no trigger recorded → **Blue**.
3. Complied or complied late → **Green**.
4. Overdue → **Red**.
5. Returned or rejected inside the Amber window → **Red**.
6. Inside the Red window → **Red**.
7. Inside the Amber window, including with evidence missing or waiting on others → **Amber**.
8. Otherwise → **Green**.

Default windows (Red / Amber):

- Immediately: 2 / 3 days.
- Daily to Monthly: 3 / 7 days.
- Quarterly and longer, and One-time with a date: 7 / 30 days.
- Event Based after the trigger: 25% / 50% of the statutory period remaining, with a minimum of 2 days for Red.

High risk widens both windows by 50%, rounded up. A predicted "At risk of slipping" flag is never written into the RAG column.

## A.13 Importer changes for v2.0 and error codes LDC-TPL-049–069 *(v1.2)*
